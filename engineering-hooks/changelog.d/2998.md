- `hold_guard.py`, a PreToolUse hook on Bash: refuses a `git push` to a branch whose PR (or the issue it closes) carries `loop:hold`, and a PR created (`gh pr create`, or a POST to `.../pulls`) for a held issue, naming the hold and who set it; removing the label lifts both. The same script is a git `pre-push` hook for an agent without Claude's Bash hook (`hold_guard.py --pre-push <remote> <url>`, refs on stdin; a Codex checkout installs it as `.git/hooks/pre-push`: `exec python3 <pack>/engineering-hooks/hooks/hold_guard.py --pre-push "$@"`). A branch's first push, before any PR exists, is refused when a commit it adds names a held issue (`Closes`, `Fixes`, `Resolves` or `Implements #n`). A hold sent as a message loses the race with the turn in flight, so the label is the hold (#2998)
