- `approvals.py`: a PR that links a sign-off issue with the wrong keyword is told so in a line naming the keyword
  the PR says, the one it needs and the label, path or spec line that requires it (`the PR says Closes #n, but #n
  waits for the owner's sign-off after landing ...: use Implements #n`), where it used to read as a description of
  the PR; `check build` on a PR runs the same check, so the keyword is fixed before the PR reaches `land`; and a
  `pre_land` refusal prints the check's last lines on every `land`, not only in its once-per-head PR comment (#1001).
