- engineering-loop: `land: gate_on: cloud` (default `host`) makes `land`, holding the lock, push the batch commit as `loop-land/<tree>` and ask one standing cloud gate session per repo to run `local-ci --record` on it, wait up to `cloud_gate_timeout_seconds` (default 2400) for that tree's record branch, delete the branch and then gate as usual, reusing the pass; a refused start, no capacity, no record in time, or a session that ended its turn with no record and no red line, prints one line and gates on the host, and a `where: host` step still runs there; a session that ended its turn on `DONE: red <tree>` (its gate ran and failed; a `failed` session state never counts, so a retry falls back to the host) makes the tree red at once, with no host re-run. The red path takes the same route. A session mid-turn takes the message queued; a dropped or half-started session is closed and its launch dir removed.
