- engineering-loop: `cloud_verifier.py verify` (both harnesses) times each pass in whole seconds as `start` (from the new optional `--requested <unix seconds>`, the time the lead asked for the pass; `unknown` without it), `setup`, `review` and `post`. The posted report gets a footer of four `Seconds:` lines and the run prints one JSON line, `{"pass_seconds": {...}, "pr": N, "head": "..."}`, before the comment URL, which stays the last line. The post time goes in by one edit of the posted comment; a failed edit is a warning and leaves `Seconds: post unknown`. A phase that did not run is `unknown` (`null` in the JSON), never 0. The `thread` route records none, since the thread API reports no phase times. (#1036)
