- `approvals.py` reads the project's policy (`docs/agents/issue-tracker.md`, `loop.md`, `gatekeeper.md`) from
  `origin/<base>`, the base the PR merges onto (the ref `land` builds on; the default branch for a command with no
  PR), not from the working tree, and `land` fetches the base before reading it and reads it again after its fetch under the lock (placing
  the land again under it, and a draft it readied that the new policy would not ready goes back to draft), so a checkout behind its base can't
  gate under an old policy and a PR can't gate itself under the policy it proposes; a working-tree copy that differs
  gets one stderr line naming the file and both commits, and a checkout without that ref reads the working tree with
  one line saying so (#1047).
