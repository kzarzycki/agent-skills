- `land` lands through the base's merge queue, picked by its ruleset: the local merge queue (the landing lock, a local batch and a local gate, as before) or, where the ruleset has a `merge_queue` rule, the GitHub merge queue, which `land` and `check merge` no longer refuse. There `land` checks every proof as before, then enqueues each landable PR oldest first with `enqueuePullRequest` pinned to its head, and GitHub's `merge_group` CI gates and merges it: no lock, local batch or local gate. A named PR in the queue exits 3, and `land --wait` follows it until it merges, then comments `Landed` with `Gate: merge queue` and the run's link. A removal for a red check gets a comment with the check's log tail and one more try, a second red on the same head turns the PR back to draft, a red main counts nothing (exit 1, `main itself is red`), nor does a red group built on a main commit where a required check failed (still running: exit 3; a cancelled run there is no failure), a conflict gets the conflict comment while GitHub reports the PR conflicting and waits while GitHub works it out, and an entry whose group commit waited 10 minutes for checks GitHub never started is dequeued and enqueued again. Each enqueued PR gets the `loop:queued` label, and a bare `land` comments `Landed` on every merged PR still carrying it, then takes the label off; a PR whose trail fails keeps it for the next land, and never fails this one. It refuses a `merge_commit_heads` head unless the queue merges with `MERGE`, `signed_squash_to`, and a cloud session (#1114).
