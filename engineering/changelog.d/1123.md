- orchestrating-agents: `omnigent_agent.py wait-for` takes `--stall <seconds>` (default 300, 0 off): a live `--pid` run that is not on the gate lock and whose `--log` has not grown for that long has its process group killed (SIGTERM, then SIGKILL after 5 s), and `wait-for` exits 1 with `stalled: no output in <log> for <n>s; killed pid <pid>'s group` and the log tail; engineering-loop's worker.md and verifier.md say a stall means the step hung, not that the change failed (#1123).
- engineering-loop: a run queued on a host gate slot (`approvals.py local-ci`, `mutate.py`) repeats its waiting line every minute, and `mutate.py` prints each log line to stdout too, so `wait-for --stall` never reads a queued or mutating run as hung; `mutate.py` runs its git calls outside its process group, so a stall kill cannot cut a tree restore short (#1123).
- engineering-loop: `land --wait` repeats an unchanged state (a lock or CI wait) every minute, and a batch gate says `Tree <tree>: gating, log <log>` every minute while its steps write to their own log, so `wait-for --stall` never kills a land, which could leave the landing lock stale (#1123).
