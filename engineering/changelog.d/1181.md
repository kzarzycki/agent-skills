- `land` runs in a cloud session on a base whose ruleset requires GitHub's merge queue, where it used to refuse. Where GraphQL answers 403, the forge port answers each queue step over the REST routes a cloud session's proxy serves: auto-merge on (`ccr/auto_merge`, the queue's merge method and the judged head) enqueues, auto-merge off dequeues a stuck entry, and the PR's queue state comes from its timeline's queue events, GitHub's `gh-readonly-queue` ref and the repo's `merge_group` runs. Right after the enable `land` reads the PR again; a head other than the judged one has auto-merge taken off and is refused, naming both heads, and the other PRs still go in. REST names no removal's reason, so each is read from its group's commit (merged, a failed required check, a conflict, or nothing), and the decisions stay the host's. A cloud land on such a base needs no `land.signing_key_env`, since GitHub signs. In a cloud session, on either merge queue, a named draft is now marked ready and an evicted PR turned back to draft through the proxy's draft routes, where both used to stay as they were (#1181).
