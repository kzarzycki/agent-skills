- engineering-loop, orchestrating-agents: a lead's own test runs go to the cloud by default. `omnigent_agent.py cloud-run [--checkout DIR] [--timeout S] -- <command>` runs one shell command in a Claude cloud session on the checkout's pushed HEAD, reusing the launch dir `<main checkout>/.worktrees/cloud-run-<branch>`, on the small model with `--permission-mode auto` and `--no-keep`; it prints the report path and exits with the command's code from the report's `EXIT:` line, refuses tracked changes or an unpushed HEAD before any session exists, and exits 125 with the reason and the host fallback when the cloud route fails. The pack ships a Claude Code `PreToolUse` hook on Bash (`hooks/hooks.json`, `hooks/host_run.py`), which APM deploys into each consuming repository's `.claude/settings.json`: in a host session of a repository whose `docs/agents/loop.md` has no `Cloud worker: none` line it refuses a heavy test or check command (pytest beyond named test files, `mise run check*`/`test*`, `make check|test`, `npm|pnpm|yarn [run] test`, `cargo test`, `go test`, `tox`, `nox`, `gradle test|check|build`, `mvn test|verify`, `approvals.py local-ci --run|--record` and `affected-tests`), naming its `cloud-run` call, and allows a command prefixed `LOOP_HOST_RUN=<reason>`, the host fallback, and any command it can't parse. A child the launcher places on a host is told the prefix in its preamble (#1233).
