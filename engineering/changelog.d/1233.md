- engineering-loop, orchestrating-agents: a lead's own test runs go to the cloud by default. `omnigent_agent.py claude-cloud-run [--checkout DIR] [--timeout S] -- <command>` runs one shell command in a Claude cloud session on the checkout's pushed HEAD (refusing tracked changes and an unpushed HEAD before any session exists), reusing `<main checkout>/.worktrees/claude-cloud-run-<branch>` as its launch dir, on the cheap model with `--permission-mode auto` and `--no-keep`, and exits with the command's code from the report's `EXIT:` line, or 125 with the reason and the host fallback when the cloud route fails. The pack ships a Claude Code PreToolUse hook on Bash (`hooks/hooks-claude.json`, which APM deploys into a consumer's `.claude/settings.json` and no Codex file) that refuses a heavy test or check command in a host session with an Omnigent server configured (`RUNNER_SERVER_URL`), inside a repo whose loop.md has no `Cloud worker: none` line, naming the `claude-cloud-run` call (without a server it allows the run and prints one line saying it stayed local); `LOOP_HOST_RUN=<reason>` is the host fallback it lets through, and a child the launcher places on a host is told to use it (#1233).
