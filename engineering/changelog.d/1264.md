- engineering-loop: `approvals.py check setup` (the gatekeeper's `check setup`) is the gate step a consumer runs on a pack upgrade: with no PR and no GitHub it reads the repo's policy as every loop step does, then scans its mise config and `.github/workflows`, and exits 1 with one line per problem for a bullet-form policy, a pack script run by a bare `python3` (no PyYAML) or a workflow job that runs one after `mise-action` installed no `uv` (`install: false`, or `install_args` without uv). The refusal of a bullet-form policy now names the file, the fenced `yaml` block and "land the migration on the base before the pin bump". **Upgrading to 0.29.x** ([README § Upgrading the pack](README.md#upgrading-the-pack)): (1) write the policy as a fenced `yaml` block (`## Policy` in gatekeeper.md, or `## Settings` in loop.md and issue-tracker.md; the bullet form is refused from 0.24.0 on), (2) run `approvals.py` and `labels.py` with `uv run` (from 0.29.0 they are `uv run --script` scripts that import PyYAML) and let the approvals workflow install uv (`install_args: uv`, no `install: false`), (3) land that migration on the base before the pin bump, since the gatekeeper reads the policy from `origin/<base>`, so a bump PR cannot carry it, (4) add `uv run --python '>=3.11' <pack>/scripts/approvals.py check setup` to the repo's `check` gate (#1264). `--python '>=3.11'` is needed because `check setup` reads mise's TOML with `tomllib`; on an older Python it refuses and names the flag.
