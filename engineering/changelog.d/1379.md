- `local-ci` writes the `gate` event (`refs/loop/gate/<branch>`): `waiting` first thing in the detaching call, then while a step waits for a host gate slot or runs, rewritten at each beat, then `ok` with the record's path as `url`, or `failed` with the detached run's log as `url` when there is one, else empty; the `gate` commit status stays on the PR head and on main commits (`land`'s `publish(tip, landed_pass(...))` writes the latter), and a failed event write never changes the gate's exit (#1379).
