- engineering-loop: narrowed gates by default (#1422). A project whose loop.md names an `Affected tests:` command (its
  selector plus its cheap whole-repo lint and type checks, as one task) now has every worker head, draft or ready,
  run it (`approvals.py affected-tests`, which takes `--base <rev>` and runs the full `mise run check` for a base git
  can't resolve), and `land`'s batch gate run it against the base tip the batch merges onto. Under `ci: false`,
  `local-ci --record` records a narrowed pass against the merge base, which `check merge` takes and which never stands
  for a full one. The line `Gate: full` returns every gate to the full check; without the `Affected tests:` line
  nothing changes, and a project with `gate_steps` keeps its steps. Before taking this release: the project template
  does not ship the push-to-main and ready-PR CI runs of `affected-tests --base` or the nightly full-suite workflow
  that calls `nightly.py red` yet, so until your CI has them, `land`'s batch gate is guarded only by the selector.
  Add those runs (this repo's own `.github/workflows` show the shape) or set `Gate: full`; SKILL.md, Adopting the loop,
  states the risk and its guards.
