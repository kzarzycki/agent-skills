- engineering, orchestrating-agents: work for a host runs in a session on that host. The pack ships a second Claude Code PreToolUse hook on Bash, `hooks/remote_run_guard.py` (registered in `hooks/hooks-claude.json` after `heavy_run_guard.py`, whose shell parsing it reuses), which refuses `ssh [options] <host> <command>` and `omnigent_agent.py ssh <host> -- <command>` when the remote command builds or tests (`make`, `mise run`, `pytest`, `xcodebuild`, `gradle`, `npm test` and the like), runs a gate or a land (`approvals.py`/`gatekeeper.py` `land`, `record`, `approve`, `delegate`, `local-ci`, `affected-tests`, `heavy`) or runs `git push`, through quoting, ssh's options, wrappers and `sh -c` on either side, in host and cloud sessions alike, with no bypass; read-only calls (`cat`/`tail` of a log, `git log`/`status`/`rev-parse`, `/proc/loadavg`, `ps`) stay allowed. Its refusal names a session on that host (`start --host`) or `claude-cloud-run`, and that a Mergify `land` and `record verdict` run in the caller's own session. orchestrating-agents' Rules state it (#1754).
