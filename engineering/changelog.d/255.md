- `supervise --registry` keeps its state where a successor or the web UI can read it (#255).
  Each poll writes `<registry>.state.json` (schema `cos-state/1`, atomically) with an entry per
  registry session (title, host, state, wait, ending, first line, `progress_at`, budgets) and the
  ids of events already posted, loaded on start, so a restart re-posts no follow end and keeps
  each lead's progress; appends each event to `<registry>.events.jsonl`; and labels each session
  with `status.line` and `status.at`, written only when the line changes or once a minute. A
  followed lead with no progress for 20 minutes, its own history and its live children counted,
  raises a `deadline` event, whatever its status reads, unless it is parked or ended with
  `DONE` or `USER NEEDED`; a nudged one with an unknown wait a second, 10 minutes later.
