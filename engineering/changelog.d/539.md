- engineering-loop: a `local-ci` pass also posts as a `local-ci` success status on its head (command, env and host as JSON in the description), and a clone without the record file reuses the newest such status by the account running `approvals.py` or a writer. So a gate recorded on one host serves `local-ci <pr>`, `check queue`, `batch` and a batch proof read by `land` on another, for the same head and env. A status GitHub refuses, or one that won't fit, leaves only the local record, as before (#539).
