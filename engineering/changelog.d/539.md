- engineering-loop: a `local-ci` pass also posts as a `local-ci` success status on its head, described as the SHA-256 of its command and env plus its host, so it fits any env. A clone without the record file reuses the newest such status (every page read) whose digest is its own command's and env's, posted by the account running `approvals.py` or a writer. So a gate recorded on one host serves `local-ci <pr>`, `check queue`, `batch` and a batch proof read by `land` on another, for the same head and env. A status GitHub refuses leaves only the local record, as before (#539).
