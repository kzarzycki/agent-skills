- engineering: the package splits into `gatekeeper`, `loop`, `github`, `chief-of-staff` and `omnigent`, each a plugin of its own in the marketplace and an APM package of its own. `engineering` keeps the craft skills, `orchestrating-agents` with its native and herdr-link backends (its Omnigent backend is the `omnigent-agents` skill now) and a new `browsing` skill holding `browse.py`. For this release line `engineering` depends on the five new packages, by `dependencies` in `plugin.json` and in `apm.yml` (`git: kzarzycki/agent-skills/<package>`, `ref: ^0.1.0`, so each package's own `<package>-v0.1.0` tag must be on the forge before this release is tagged), so a project pinned to it still installs every skill it had; the next minor release drops them, and `loop` and `omnigent` then depend on `engineering`, since both at once is a cycle (#615).
- orchestrating-agents: `scripts/omnigent_agent.py` keeps working for this release line: it runs the `omnigent-agents` skill's omnigent_agent.py with the same arguments, stdin and exit code, after one deprecation line on stderr naming the new path. It goes away with the release that drops `engineering`'s dependencies on the packages split out of it (#615).
