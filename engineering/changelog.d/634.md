- orchestrating-agents: `omnigent_agent.py wait-for` is the one way a role waits on a run or a PR. Given a log with an `exit <n>` line, a pid (or pid file) or `--pr N --until checks|merged|closed`, it blocks up to `--budget` (default 570 s, under a 10-minute tool call), prints nothing while waiting, and ends with the run's exit code and its summary line, the last 30 lines on red, or `still running` (exit 6). A pid file's process younger than the file counts as gone, since that pid was reused. `--notify` runs `$LOOP_NOTIFY <outcome>` once the run ends, as a merge queue tells a lane, so the detached-run recipe tells the session that started it, and that session can end its turn. lead.md, worker.md and verifier.md now name `wait-for` where they used to say to block near the tool limit with a sleep loop of your own (#634).
