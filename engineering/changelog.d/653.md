- `approvals.py land [<pr>] [--wait]` lands every landable PR into the base as one gated batch: it takes the lock `refs/loop/landing` on `origin` (a stale one, older than 2 hours, is broken), merges the heads of every ready PR whose merge proofs hold onto the base in a temporary worktree, oldest first, gates the result's tree once or reuses a pass on it, then merges each PR through GitHub in that order (or as a signed squash of the gated tree) and checks the base ended at the gated tree, commenting `Landed` on each. A conflicting PR is skipped with one comment per head; a red batch lands one PR at a time, evicting a PR red alone twice back to draft with its log's tail, and a red bare base stops the run evicting nobody. The per-PR path is gone: auto-merge, GitHub merge queue handling, the `BEHIND`/`DIRTY` refusals and the approvals-run rerun. `check queue`, `batch`, `batch_queue`, `carry_over_main` and `ci` still work and print a `deprecated:` line each (#653).
