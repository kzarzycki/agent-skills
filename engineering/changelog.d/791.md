- engineering-loop: the policy's `risk.merge_paths`, a list of globs beside `risk.paths`, holds the merge of any PR touching a matching path for the owner's own go on its head, whatever its labels, `spec.auto` and the verifier's `Risk:` line say, into any branch. `check merge`, `check queue` and `land` wait for that go and name the matching path, a new push needs a new go, and `approve merge --by delegate`, `delegate` and `approved:merge` give none there. Without the setting nothing changes. A rule's paths (`risk.paths`, `risk.merge_paths`, `signoff`) now match a renamed or copied file's old name as well as its new one, read from GitHub's REST file list and holding when GitHub won't give it, and `check build` before the PR lists a moved file's old name too, so moving a file out of a listed directory no longer slips past the rule (#791).
