# MISSION.md Format

`MISSION.md` lives at the workspace root and holds the reason the user is learning the topic. What to teach next, which resources to surface and which exercises to design all trace back to it.

```md
# Mission: {Topic}

## Why
{1-3 sentences: the concrete outcome the user is chasing, not "to understand X".}

## Success looks like
- {A specific, observable thing the user will be able to do}

## Constraints
- {Time, budget, commitments, learning preferences}

## Out of scope
- {Adjacent topics the user does not want to chase now}
```

- One mission per workspace; two unrelated topics are two workspaces.
- Concrete: "run a half marathon by October", not "get fitter".
- If the user cannot say why, interview them before writing anything. A bad mission is worse than none.
- Keep it under a screen; longer, it has become a plan.
