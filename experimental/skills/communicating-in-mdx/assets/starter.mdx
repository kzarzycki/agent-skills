# communicating-in-mdx — what it is

This file is the exemplar. It shows the house style: **prose carries the
meaning, components enhance it.** Read it top to bottom — if you stripped every
component tag, the prose would still make sense. That's the rule.

The skill lets an agent write specs, plans, designs, and recaps as MDX and
render them with a fully local runner. Nothing is uploaded anywhere.

<Callout tone="decision" title="The one decision that shapes everything">
The `.mdx` file is the artifact — git-diffable, hand-editable, shareable. The
rendered page is transient. HTML is never a deliverable.
</Callout>

## How rendering works

You share MDX; rendering is a local function anyone with the runner applies.

## MDX vs the HTML skill

They coexist. Pick by what you need.

<Columns>

**MDX** — lighter to author (prose + tags), the source is durable and
re-renderable, but it needs the runner.

**HTML** — zero dependencies, renders for anyone by double-click, but you
hand-write the layout.

</Columns>

wanted.
