- `loop-gate/<tree>-<key>` record branches no longer pile up on origin (#1869). Only `land`'s own merge deleted them, so a PR merged through Mergify or a merge queue, merged by hand, or closed unmerged left its records behind, and a cloud session cannot delete a ref. New `approvals.py prune-records [--head <sha>...]` runs the same deletion (`drop_records`), and the new `prune-records.yml` workflow runs it when a PR closes (naming its head, so its tree's records go at once) and daily (a record over a day old whose tree is no open PR's head). It checks out the base branch only and runs no PR code.
