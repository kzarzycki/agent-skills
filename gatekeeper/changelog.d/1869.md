- `loop-gate/<tree>-<key>` record branches no longer pile up on origin (#1869). Only `land`'s own merge deleted them, so a PR merged through Mergify or a merge queue, merged by hand, or closed unmerged left its records behind, and a cloud session cannot delete a ref. Now every `land` ends with the same sweep (new `approvals.py prune-records [--head <sha>...]` runs it by hand): it deletes the records of each named PR that is merged by then, and any record over a day old whose tree is no open PR's head. A refused delete or unreadable PR list is one warning line and never fails the land. A consuming repo gets this with the release, with no workflow to add.
