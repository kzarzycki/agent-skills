- gatekeeper: `land --wait` asks GitHub only when what it waits on moved. Between two rounds it reads, every 30 s, only that: a land behind the landing lock reads the lock with one `git ls-remote` and makes no GitHub call until the lock moves past its holder's heartbeat (or stops beating for 15 minutes); a wait on a named PR's CI reads the base and the heads with one ls-remote and each head's check runs and statuses with an ETag (`If-None-Match`), which GitHub answers 304 at no quota while nothing changed, and runs the round again once a head, the base or a required check's state moved, or the base's lock is freed, else after 15 minutes; it starts from what the round read, and a failed probe runs the round rather than ending the wait. The PR's `waiting` event and the land's place in the waiting order are still stamped every 5 minutes, by git push. `tests/test_land_wait_budget.py` counts the gh calls of one poll round of each wait state and fails above its budget (#1915).
