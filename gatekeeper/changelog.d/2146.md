- gatekeeper: a queue red on a diff no test can reach is retried, never counted against the head (#2146). When the PR's changed files hold no `select.build_inputs` file and touch no `select.checks` path (the cut `affected-tests` runs by), a `failed_checks` removal from GitHub's merge queue, or a dequeue by Mergify, leaves the PR ready and enqueues it again, so a flaky test or a loaded runner no longer turns an unrelated PR back to draft on its second red. After 3 such reds at one head the next counts as any other, so a suite broken everywhere still stops the PR; a diff that reaches a test, and a project with no `select`, count every red as before. The GitHub queue also retries a red whose every failed test (the `FAILED <id>` lines of the failing job's log) has an open `Flaky: <test id>` issue, counting it against the same 3 retries; a log with no such line, or one test without an issue, counts as before (the Mergify path has no failed-test log to read, so it keeps the diff-level rule only). A pre-push hook calls `affected-tests` for the same cut: a CI-only diff selects no product test.
