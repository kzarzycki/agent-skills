- gatekeeper: one `timeouts` block in gatekeeper.md (`test: 60s`, `run: 60m` by default, today's values) sets every time limit of a run, so raising one moves the others: the Mergify queue's `checks_timeout` (`approvals.py queue-config`, and `gatekeeper.py timeouts --mergify`, render it into `.mergify.yml`, `timeouts --check` and `check setup` say when the file is out of step), a CI job's `timeout-minutes` (printed by `gatekeeper.py timeouts` for the templates that render workflows) and `land --wait`'s ceiling, the queue's checks timeout plus one more run (2 hours with nothing set, 8 hours with `run: 4h`). `land.wait` is deprecated: a set value still overrides the ceiling, with a `deprecated:` line. The landing lock's staleness stays 2 hours. A malformed duration is refused, naming the key. `affected-tests` stops a run still going at `timeouts.run` and exits 124 with one line naming the budget, the selection's size where it knows it (the whole suite under `Gate: full`; else unknown, with the count of changed files) and that it ran unsharded. A timeout is never a test's failure: a GitHub merge queue removal whose required checks only timed out counts for nothing, and a Mergify dequeue its check run calls a timeout is queued again instead of evicted (#2228).
