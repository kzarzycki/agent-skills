- gatekeeper: `timeouts.run` stays the one gate budget, and a selection over it fails fast (#2445). `timeouts --check` now also names, one line each, a marked workflow job's `timeout-minutes` (`# timeouts.run` after it), the variable loop.md's `Wall-clock variable:` names, a hand-set `land.wait`, and a nightly workflow (`# timeouts: nightly`) whose push paths differ from `select.build_inputs`. `durations --record` turns the nightly's JUnit XML or `--durations=0` output into the durations file `shards --durations` reads. `affected-tests` estimates a whole-suite run (recorded seconds over `GATE_WORKERS`, plus `GATE_SETUP_SECONDS`; per shard under `select.shards`) and exits 124 in one line when it is over 80% of `timeouts.run`; with no recorded durations it says so and runs. Each run records its estimate beside its actual time, and `durations --report` flags drift over 25%. New `select.build_inputs_in_queue: floor | full` (default `full`; a project opts into `floor` once its nightly records durations and runs on a push touching build inputs): in the merge queue a build input selects the other changed files' tests plus, for `uv.lock`, the tests that import a package whose version moved, and the run after merge covers the rest.
